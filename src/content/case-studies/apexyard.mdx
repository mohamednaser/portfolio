## Context

Engineering teams shipping multiple repos need the same discipline everywhere: ticket-first work, code review, merge gates, security review on auth changes, and dependency audits — without re-inventing process per repository.

## What we rolled out

**ApexYard** is an ops-repo pattern: fork a single `apexyard` stack, register every managed project in `apexyard.projects.yaml`, and drop `.claude/` hooks + skills into each workspace. Agents (Code Reviewer, Security Reviewer, PR Manager) and 30+ slash commands (`/start-ticket`, `/approve-merge`, `/audit-deps`) encode the SDLC as executable workflow.

Mechanical enforcement matters: `block-main-push`, `require-active-ticket`, `validate-pr-create`, and CEO merge approval are shell hooks — not guidelines in a wiki.

## How AI was introduced

Claude Code is the runtime. Roles in `roles/` activate on triggers (auth diff → Security Auditor, new PRD → PM). AgDRs record agent decisions. The portfolio registry lets `/inbox`, `/status`, and `/tasks` aggregate across repos.

## Outcomes

- One place to govern blog-generator, portfolio, and future products
- PR quality is consistent: ticket IDs, glossaries, Rex review before merge
- New projects onboard via `/handover` with a structured assessment instead of ad-hoc READMEs

## Lessons learned

- **Hooks beat docs** when you are the only human in the loop — future-you will skip optional checklists.
- **Per-PR CEO merge approval** prevents "ship the plan" from becoming "ship everything."
- Keep the ops repo separate from product repos so framework changes do not collide with feature velocity.
